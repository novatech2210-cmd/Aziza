2.1 — TOKENIZER AUDIT
Goal
Measure fertility (tokens-per-word) for Russian and Uzbek against the English baseline. If fertility > 2.5× English →
vocab extension required before training. If within threshold → proceed directly to dataset prep.

Commands
pip install transformers datasets sentencepiece sacremoses accelerate peft bitsandbytes trl -q
python3 audit_tokenizer.py \ --model nvidia/personaplex-7b-v1 \ --languages en ru uz_latin
uz_cyrillic \ --samples 1000 \ --output tokenizer_audit.json

audit_tokenizer.py — write this first
1. Load AutoTokenizer from nvidia/personaplex-7b-v1
2. For each language: tokenize 1,000 sentences from Common Voice text
3. Compute fertility = total_tokens / total_words (split on whitespace)
4. Print table: language | fertility | verdict (PASS <2.5x / FAIL >2.5x)
5. Save JSON with all metrics → tokenizer_audit.json

3.1 — NESTJS SESSION ORCHESTRATOR
What it does
Central routing layer. Creates sessions, assigns GPU workers, tracks session state in Redis, dispatches PersonaPlex
persona at session start.

Key endpoints to implement
Endpoint

Behaviour

POST /session/create

Validate caller → assign GPU worker → inject persona via PersonaPlex → return
session_id + WS URL

GET /session/:id/status

Return active | paused | terminated + GPU worker health

POST /session/:id/persona

Hot-swap PersonaPlex persona mid-session (no audio interrupt)

DELETE /session/:id

Graceful terminate → release GPU worker → flush Redis state

GET /workers/health

List all GPU workers + VRAM usage + active session count

POST /workers/:id/drain

Drain worker before restart (reject new sessions, finish active)

Redis data model

Session lifecycle — single-stream-per-GPU rule
■ One active Moshi stream per GPU worker — locked architectural decision from Phase 1.
Do NOT allow concurrent sessions on same worker. Assign → lock → release.
■ Worker assignment: round-robin over idle workers. If all busy → queue or reject with 503.
■ OOM guard: FastAPI worker reports VRAM on heartbeat. If > 70GB used → mark worker full.
■ Persona injection: PersonaPlex /text endpoint called at session start with system_prompt.
Hot-swap: POST /session/:id/persona triggers new injection without stream restart.

3.3 — ASTERISK ARI INTEGRATION
Call flow — exact sequence
1. PSTN/SIP call arrives → Asterisk matches dialplan → enters Stasis app "aziza"
2. ARI StasisStart event fires → Aziza ARI client receives it
3. ARI client POSTs to NestJS /session/create { callerId, language, register }
4. NestJS assigns GPU worker, injects PersonaPlex persona, returns { session_id, ws_url }
5. ARI client opens WebSocket to FastAPI /ws/speech?session_id=...
6. ARI client opens Asterisk media socket, starts ExternalMedia bridge
7. Audio flows: Asterisk µ-law 8kHz → ARI client → resample 24kHz PCM → Moshi WS
8. Moshi response PCM 24kHz → downsample 8kHz µ-law → Asterisk → caller hears Aziza
9. WebRTC VAD runs on client side — detects end-of-utterance → signals Moshi
10. On hangup: ARI StasisEnd → ARI client DELETEs session → GPU worker released

Asterisk dialplan — add to extensions.conf or AEL
[from-pstn]
exten => _X.,1,NoOp(Aziza inbound)
same => n,Stasis(aziza)
same => n,Hangup()
# ARI config in ari.conf:
[general]
enabled = yes
pretty = yes
[aziza]
type = user
password =
read_only = no
