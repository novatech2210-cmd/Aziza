## 1. System Classification

**System Type:** Hybrid — Multi-Mode Conversational AI (Text-to-Text LLM Serving + Streaming Voice Inference) + Multi-Agent Orchestration + Fine-Tuning Pipeline

**Description:**
Aziza is a multi-mode AI assistant supporting three interaction modes behind a single orchestrator:

1. **Text-to-text** — served via **Ollama** running a **Vikhr** model (Russian-tuned LLM), for chat/text sessions with no audio component.
2. **Voice-to-text** — speech input transcribed via a dedicated Russian ASR service (`ru_colloquial` adapter) and routed to the text-to-text backend for response generation.
3. **Voice-to-voice** — full-duplex, real-time speech-to-speech via **NVIDIA PersonaPlex-7B** (Moshi/Helium backbone), accepting raw PCM audio and streaming Opus-encoded audio responses with a <250ms TTFT target.

All three modes share a common API gateway, Redis-backed session/control plane, and persona/system-prompt layer. The platform is deployed on **Proxmox-hosted VM infrastructure** (not Vast.ai), with the primary compute node `aziza-worker-01` (internal IP `10.10.10.11/24`, public-facing IP `83.126.40.54`, SSH port 122), administered via a Proxmox panel at `83.126.40.53:8006`.

**Critical Failure Modes:**
1. **Ollama service offline:** `ollama serve` not running / not bound correctly → `ECONNREFUSED` on port `11434`, hard-blocking the entire text-to-text mode (and by extension, voice-to-text, since transcripts route through the same LLM backend).
2. **Deploy path mismatch:** `deploy_rsync.py` syncs to a path that doesn't match the service's actual working directory or systemd/PM2 unit, so deployed code is never picked up by the running process.
3. **Missing reverse proxy config:** No Nginx `sites-enabled` entries configured for `aziza-worker-01` → no SSL termination, no consistent routing for gateway/ASR/voice endpoints, services only reachable on raw ports.
4. **Audio corruption (dtype mismatch, voice-to-voice only):** int16 PCM samples not normalized to `[-1,1]` before Mimi encode → Moshi generates silence tokens every step. Root cause confirmed in `moshi_engine.py`.
5. **Ghost sessions / GPU leak (voice-to-voice only):** Client disconnects without `stop_audio` signal → moshi-worker holds GPU allocation indefinitely, blocking subsequent connections.
6. **Orchestrator crash loop:** `SessionState` Enum serialized as object (not `.value`) → Redis `DataError` → orchestrator restarts, dropping all active sessions across **all three modes**, since the orchestrator is shared.
7. **dep_q mismatch (voice-to-voice only):** Training with `dep_q=8` instead of `dep_q=16` → corrupted audio output from fine-tuned adapters.
8. **Disk pressure:** `aziza-worker-01` was at 69% full (~30GB free) as of the last audit — fine-tuning artifacts and model pulls (Ollama models, LoRA checkpoints) can exhaust this quickly; needs monitoring before Week 3 fine-tuning work begins.
9. **Single-worker starvation (voice-to-voice only):** Concurrent WebSocket connections assigned to the same GPU worker → OOM, crash, no graceful 503.

## 1b. Domain Context

**Industry Vertical:** Conversational AI — Text Chat, Speech-to-Text, and Real-Time Voice (Telephony-capable)

**User Population:** End-users via text/chat clients, browser WebSocket voice clients (`localhost:5173` Vue test frontend), and (Phase 3) SIP/PSTN callers via Asterisk ARI for the voice-to-voice mode.

**Stakes Level:**
- Text-to-text: Medium — incorrect or off-persona responses are visible but not real-time-perceptible as "broken."
- Voice-to-text: Medium-High — transcription errors propagate into LLM context and degrade response relevance.
- Voice-to-voice: High — real-time audio; corruption or silence is immediately perceptible and breaks the product.

**Output Consequence:** Text responses (modes 1–2) are displayed/spoken via TTS-adjacent paths; voice-to-voice responses are streamed live audio to a caller. Errors manifest as wrong-language replies, transcription drift, silence, audio artifacts (screech), or dropped sessions.

### What Domain Experts Evaluate Against

| Dimension | Good (expert accepts) | Bad (expert flags) | Stakes | Mode(s) |
|---|---|---|---|---|
| **Response latency (text)** | First token <1s after request | >3s → perceptible lag | Medium | Text-to-text, Voice-to-text |
| **ASR accuracy** | Russian colloquial speech transcribed with <10% WER | Frequent mis-transcriptions altering intent | High | Voice-to-text |
| **TTFT (voice-to-voice)** | First audio token <250ms after user stops speaking | >500ms → perceptible lag | High | Voice-to-voice |
| **Audio fidelity** | Clean 24kHz voice, no screech/artifacts | Any high-frequency corruption >-40dBFS | Critical | Voice-to-voice |
| **Language accuracy** | Russian/Uzbek phonetics and grammar match adapter register | English phonemes/words bleeding into Russian response | High | All modes |
| **Persona consistency** | System prompt honored across full conversation, all modes | Persona drift mid-conversation or across mode switches | Medium | All modes |
| **Session isolation** | Each user/caller gets clean state | State leaking between sessions | Critical | All modes |
| **Recovery** | Screech auto-detected and session reset | Screech continues for >2s | High | Voice-to-voice |

### Known Failure Modes in This Domain
- **Backend unavailable:** Ollama not running means modes 1 and 2 fail silently or with connection errors at the orchestrator layer — needs an explicit health check, not just a timeout.
- **Screech:** High-frequency audio corruption when the PersonaPlex model output diverges; requires spectral detection + session reset (voice-to-voice only).
- **Silence loop:** When audio input is not in expected float32 `[-1,1]` range, Mimi encodes silence tokens; model never generates speech (voice-to-voice only).
- **ASR/LLM handoff drift:** Voice-to-text transcripts that omit punctuation or merge sentences can confuse the Vikhr model's turn-taking; needs a normalization step before handoff.
- **Context window exhaustion:** Long sessions (text or voice) exceed LM context → repetition or hallucination.
- **Adapter bleed:** Wrong LoRA/model variant loaded for session language → wrong phoneme or lexical distribution.

### Regulatory / Compliance Context
- No PII stored beyond session duration (Redis TTL on all session keys).
- Audio is not persisted server-side in production (stream-only) for voice-to-voice; voice-to-text transcripts retention policy: `<!-- TODO: confirm retention window for ASR transcripts -->`.
- Telephony compliance (Phase 3, voice-to-voice): standard Asterisk ARI — no GDPR special category data.

## 2. Framework Decision

**Selected Framework:** Hybrid stack — **Ollama** (text-to-text LLM serving, Vikhr model) + Russian ASR service (voice-to-text) + custom aiohttp + PyTorch + sphn (voice-to-voice, PersonaPlex/Moshi) + moshi-finetune FSDP+LoRA (training) + API gateway (WebSocket) + Redis (session/control plane)

**Version:**
- `ollama`: `<!-- TODO: confirm pinned version on aziza-worker-01 -->`
- Vikhr model tag: `<!-- TODO: confirm exact model tag pulled into Ollama -->`
- ASR service: Russian, `ru_colloquial` adapter, port `8020` — confirmed healthy in last audit
- `personaplex` fork: pinned at `nvidia/personaplex-7b-v1`
- `moshi-finetune`: vendored in `personaplex-finetune/moshi-finetune/`
- `sphn`: latest compatible with PersonaPlex (installed via `pip install moshi/.`)
- Redis: confirmed healthy on port `6379`
- API gateway: WebSocket confirmed healthy on port `8080`
- PyTorch: `>=2.3.0` with CUDA 12.x

**Rationale:**
Ollama is used for text-to-text because it gives simple local serving of the Vikhr model without the latency and protocol overhead of a wrapper framework, and because it's already the locked decision for this mode — no LangChain/LlamaIndex layer is introduced on top of it. PersonaPlex retains its own official `aiohttp` + `sphn` server implementation for voice-to-voice, since that protocol is binary/streaming and wrapping it would add 50–200ms of overhead and hide the WebSocket protocol. Voice-to-text sits between the two: ASR output is normalized and handed to the same Ollama/Vikhr backend used for text-to-text, so persona and conversation logic stay in one place rather than being duplicated per mode.

**Alternatives Considered:**
| Framework | Ruled Out Because |
|-----------|------------------|
| LangChain | No native support for binary WebSocket streaming (voice-to-voice); unnecessary abstraction over Ollama for text-to-text |
| LlamaIndex | RAG-focused; no speech-to-speech primitives |
| FastAPI for the voice-to-voice WebSocket | aiohttp is the official PersonaPlex server framework; switching breaks `web.WebSocketResponse` pattern |
| Triton Inference Server | Overkill; PersonaPlex uses torch.cuda graphs internally; Triton breaks this |
| vLLM / TGI for text-to-text | Ollama already locked in for simplicity of local model management on Proxmox VM; revisit only if throughput becomes a bottleneck |

**Vendor Lock-In Accepted:** Partial — locked to NVIDIA PersonaPlex model and sphn codec for voice-to-voice; Ollama for text-to-text (swappable backend, low lock-in). Moshi backbone (Kyutai) is open-source; sphn is replaceable with opuslib if needed.

```python
async def handle_chat(request):
    ws = web.WebSocketResponse()
    await ws.prepare(request)

    # Send handshake
    await ws.send_bytes(b"\x00")

    opus_reader = sphn.OpusStreamReader(state.mimi.sample_rate)
    opus_writer = sphn.OpusStreamWriter(state.mimi.sample_rate)

    async def recv_loop():
        async for msg in ws:
            if msg.type == aiohttp.WSMsgType.BINARY:
                payload = msg.data[1:]  # strip 0x01 tag
                opus_reader.append_bytes(payload)

    async def infer_loop():
        while True:
            pcm = opus_reader.read_pcm()
            if pcm is None or pcm.shape[-1] == 0:
                await asyncio.sleep(0.001)
                continue
            chunk = torch.from_numpy(pcm)[None, None].to(device)
            codes = state.mimi.encode(chunk)
            tokens = state.lm_gen.step(codes[:, :, 0:1])
            if tokens is not None:
                audio = state.mimi.decode(tokens[:, 1:9])
                opus_writer.append_pcm(audio[0, 0].cpu().numpy())
            msg = opus_writer.read_bytes()
            if len(msg) > 0:
                await ws.send_bytes(b"\x01" + msg)

    await asyncio.gather(recv_loop(), infer_loop())
```

### Common Pitfalls
1. **Ollama not running:** `ollama serve` must be a supervised process (PM2 or systemd) — a manual `&` background launch will not survive a reboot or crash. This was confirmed offline in the last audit.
2. **`deploy_rsync.py` path mismatch:** Verify the rsync target path matches the actual working directory referenced by the PM2/systemd unit for each service before assuming a deploy took effect.
3. **No Nginx config:** Without `sites-enabled` entries, gateway/ASR/voice endpoints are only reachable on raw ports — fine for internal testing, not acceptable for any external-facing rollout (including Phase 3 telephony).
4. **`dep_q=8` vs `dep_q=16` (voice-to-voice):** PersonaPlex MUST load with `dep_q=16`. The `_load_hook` in `loaders.py` enforces this — but custom loading code can bypass it silently.
5. **`streaming_forever()` must be called once (voice-to-voice):** Calling it multiple times or forgetting it causes the CUDA graph capture to fail on the second session.
6. **`pcm is None` check before `.shape` (voice-to-voice):** `opus_reader.read_pcm()` returns `None` when no data is buffered — always check before accessing shape attributes.
7. **AZIZA-specific (voice-to-voice):** `audio_chunk` arrives as `np.int16` from `np.frombuffer()` — must normalize with `.astype(float32) / 32768.0` before `mimi.encode()`. Do NOT use `np.array(chunk, dtype=float32)` without normalization.
8. **Lock contention (voice-to-voice):** `ServerState.lock` must be held during the full inference step — concurrent sessions on one worker cause CUDA memory corruption.
9. **Disk space:** `aziza-worker-01` was at 69% full with ~30GB free at last check — Ollama model pulls and LoRA checkpoints can exhaust this; check `df -h` before any model pull or fine-tuning run.

## 4. Implementation Guidance

**Model Configuration:**
- **Text-to-text:** Vikhr model served via Ollama. `<!-- TODO: confirm exact model tag, context length, quantization -->`
- **Voice-to-text:** `ru_colloquial` ASR adapter on port `8020`, output routed to the same Ollama/Vikhr backend as text-to-text.
- **Voice-to-voice:** `nvidia/personaplex-7b-v1` (HuggingFace), `bfloat16` precision on GPU; `dep_q=16` (hard requirement, enforced by `loaders._load_hook`); `audio_silence_frame_cnt = int(0.5 * frame_rate)`; frame size `sample_rate / frame_rate = 24000 / 12.5 = 1920` samples; warmup of 4 dummy inference passes before serving.

**Core Pattern:**
A shared orchestrator routes each session to one of the three mode handlers based on `mode` in the session payload (`text`, `voice_to_text`, `voice_to_voice`). All three modes share the same Redis-backed session metadata and persona/system-prompt layer, so persona consistency holds across mode switches within a conversation. Voice-to-voice retains its dedicated multi-session Redis pub/sub channel pattern (`session:{id}:audio_in` / `session:{id}:audio_out`) for the moshi-worker; text and voice-to-text modes use simpler request/response routing through the API gateway to Ollama.

**Tool Use:**
- Redis: session state, audio streaming, pub/sub control signals (confirmed healthy, port `6379`)
- API gateway: WebSocket broker (confirmed healthy, port `8080`)
- PM2 or systemd: process supervision for all microservices, **including Ollama** — must not be run as an ad hoc background process
- Nginx: SSL termination, WebSocket proxy, routing across all three modes — **currently not configured, needs setup**
- Prometheus: metrics scraping from a `/metrics` endpoint
- Asterisk ARI: telephony bridge (Phase 3, voice-to-voice only)

**State Management:**
- Session state in Redis hash `session:{id}:meta` — status, prompts, mode, adapter (if voice-to-voice)
- Worker assignment in Redis hash `worker:{id}:state` — active sessions, VRAM (voice-to-voice GPU worker only)
- Heartbeat TTL: 10s on `worker:{id}:heartbeat` — stale workers pruned
- SessionContext in-memory in SessionManager for fast access; Redis is source of truth

**Context Window Strategy:**
- Text-to-text / voice-to-text: monitor token count per session against Vikhr's context limit; truncate or summarize older turns when approaching the limit. `<!-- TODO: confirm context limit for the pinned Vikhr tag -->`
- Voice-to-voice: PersonaPlex uses `streaming_forever(1)`, which manages the KV cache automatically for single-stream operation. For long calls (>5 min), monitor `lm_gen._cache_position` — if approaching model max context, gracefully reset via `lm_gen.reset_streaming()` and re-inject the system prompt tokens.

## 4b. AI Systems Best Practices

### Structured Outputs with Pydantic
```python
from pydantic import BaseModel, field_validator
from typing import Optional, Literal

class SessionStartPayload(BaseModel):
    sessionId: str
    mode: Literal["text", "voice_to_text", "voice_to_voice"]
    text_prompt: Optional[str] = ""
    voice_prompt: Optional[str] = None      # voice-to-voice only
    adapter: Optional[str] = None           # e.g. "ru_colloquial" — used for ASR and/or voice-to-voice
    language: Optional[str] = "ru"          # ru | uz_latin | uz_cyrillic

    @field_validator("adapter")
    @classmethod
    def validate_adapter(cls, v):
        valid = {"ru_professional", "ru_colloquial", "ru_academic",
                 "uz_latin", "uz_cyrillic", None}
        if v not in valid:
            raise ValueError(f"Unknown adapter: {v}")
        return v

class TextTurnPayload(BaseModel):
    session_id: str
    text: str

class AudioChunkPayload(BaseModel):
    session_id: str
    data: bytes  # raw int16 PCM

class InferenceResult(BaseModel):
    session_id: str
    mode: Literal["text", "voice_to_text", "voice_to_voice"]
    text: Optional[str] = None
    audio: Optional[bytes] = None   # float32 PCM bytes — voice-to-voice only
    text_tokens: list[str] = []
    screech_detected: bool = False  # voice-to-voice only
```

### Async-First Design
All inference is async. Key rules:
- Never `await` inside `torch.no_grad()` blocks — use `asyncio.get_event_loop().run_in_executor()` for blocking model calls if needed
- `asyncio.Lock` per ServerState instance — one inference step at a time per voice-to-voice worker
- Redis pub/sub uses an async client throughout — no sync `redis-py` in async code
- Ollama calls (text-to-text, voice-to-text) should use an async HTTP client (e.g. `httpx.AsyncClient`) so they don't block the event loop shared with voice-to-voice handling

### Prompt Engineering Discipline
```python
def wrap_system_prompt(text: str) -> str:
    cleaned = text.strip()
    if cleaned.startswith("<system>") and cleaned.endswith("<system>"):
        return cleaned
    return f"<system> {cleaned} <system>"

# Russian professional persona example — used for ALL modes
AZIZA_RU_PROFESSIONAL = wrap_system_prompt(
    "Ты — Азиза, профессиональный русскоязычный ассистент компании Novatech. "
    "Говори чётко, используй профессиональную лексику. "
    "Имя пользователя: {user_name}."
)
```
For text-to-text and voice-to-text, the wrapped prompt is passed as the `system` message to Ollama. For voice-to-voice, it is tokenized via `sentencepiece` at session start and stored as `lm_gen.text_prompt_tokens`, loss-masked during training (`system_prompt: true` in config). Using the same wrapped-prompt convention across modes keeps persona definitions reusable.

- **Voice-to-voice:** Frame rate 12.5 Hz → 750 frames/minute. Monitor `lm_gen._cache_position` every 100 frames; reset trigger `_cache_position > 0.85 * max_context` → re-inject system prompt.
- **Text-to-text / voice-to-text:** Track cumulative token count per session; trigger summarization or truncation at `<!-- TODO: confirm threshold once Vikhr context limit is known -->`.

## 6. Guardrails

### Online (Real-Time)
| Guardrail | Trigger | Intervention | Mode |
|---|---|---|---|
| **Ollama health check** | `/api/tags` (or equivalent) fails or times out | Mark text-engine as `down`, return graceful error to client, alert | Text-to-text, Voice-to-text |
| **Screech detector** | RMS of high-freq band (>8kHz) > threshold for 3 consecutive frames | Reset session, re-inject system prompt, log event | Voice-to-voice |
| **Silence guard** | `mean_abs(audio_np) < 0.0001` for >5 consecutive chunks | Log warning; if >20 chunks, flag session as degraded | Voice-to-voice |
| **VRAM OOM guard** | `nvidia-smi` VRAM >72GB | Mark worker as `draining`; reject new sessions with HTTP 503 | Voice-to-voice |
| **Session TTL** | No input received for >30s | Publish `stop_audio`/close session, release GPU slot | All |
| **dtype guard** | `audio_np.dtype != float32` or values outside `[-1.1, 1.1]` | Reject chunk, log error with dtype and range details | Voice-to-voice, Voice-to-text |
| **Disk guard** | Disk free <15% on `aziza-worker-01` | Block new model pulls / fine-tuning runs, alert | All (shared host) |

### Offline (Flywheel)
| Metric | Sampling Strategy | Action on Degradation |
|---|---|---|
| Ollama uptime | Continuous health probe, every 30s | Alert if 2 consecutive failures; escalate to on-call |
| ASR accuracy | 10% random sample of voice-to-text sessions | Re-evaluate ASR adapter if WER >15% |
| Language accuracy | 10% random sample of all sessions, all modes | Re-evaluate training/prompt data if <85% correct |
| TTFT p95 (voice-to-voice) | All sessions (cheap code metric) | Alert if >500ms; investigate CUDA graph capture |
| Screech event rate | All voice-to-voice sessions | If >5% of sessions trigger screech, audit audio pipeline |
| Session duration | All sessions, all modes | Abnormally short (<5s) → client-side bug; abnormally long (>10min) → memory/context audit |

## 7. Production Monitoring

**Tracing Tool:** Arize Phoenix (self-hosted on `aziza-worker-01`, port 6006) + PM2/systemd log aggregation

**Key Metrics to Track:**
```
aziza_ollama_up (gauge)               — 1/0 health status
aziza_text_ttft_seconds (histogram)    — p95 <1s gate (text-to-text)
aziza_asr_latency_seconds (histogram)  — p95 <1.5s gate (voice-to-text)
aziza_ttft_seconds (histogram)         — p95 <250ms gate (voice-to-voice)
aziza_session_active (gauge)           — concurrency vs worker count, by mode
aziza_gpu_vram_used_gb (gauge)         — alert >72GB (voice-to-voice)
aziza_disk_free_pct (gauge)            — alert <15% on aziza-worker-01
aziza_session_errors_total (counter)   — any spike in 5-min window, by mode
aziza_screech_events_total (counter)   — quality degradation signal (voice-to-voice)
aziza_audio_mean_abs (histogram)       — confirm normalization is healthy (voice-to-voice)
```

**Alert Thresholds:**
| Metric | Threshold | Action |
|---|---|---|
| `aziza_ollama_up` | 0 for >60s | Page on-call; restart Ollama via PM2/systemd |
| `aziza_text_ttft_seconds` p95 | >3s | Investigate Vikhr load / Ollama resource contention |
| `aziza_asr_latency_seconds` p95 | >1.5s | Investigate ASR service load |
| `aziza_ttft_seconds` p95 | >500ms | Page on-call; check CUDA graph + VRAM |
| `aziza_gpu_vram_used_gb` | >72GB | Auto-drain worker; page if all workers drain |
| `aziza_disk_free_pct` | <15% | Block model pulls; page on-call to clear space |
| `aziza_screech_events_total` | >3 in 5min | Investigate audio pipeline + model state |
| `aziza_session_errors_total` | >10 in 5min | Check orchestrator + Redis connectivity |

**Smart Sampling Strategy:**
- Always sample sessions that triggered a screech event or an Ollama-down error
- Sample 20% of sessions >5 min (long-call/long-chat stability), any mode
- Sample 100% of sessions where `screech_detected=True`
- Sample 5% random for baseline quality tracking, across all three modes
